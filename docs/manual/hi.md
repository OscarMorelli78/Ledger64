# Ledger64 — दस्तावेज़ (हिन्दी)

छोटे और मध्यम व्यवसायों के लिए ओपन सोर्स इनवॉइस ऑडिट, खरीद लागत तुलना और वित्तीय शासन। C64 प्रेरित इंटरफ़ेस, बाहरी एआई के बिना स्थानीय प्रसंस्करण।

**रिलीज़ कैंडिडेट: केवल कृत्रिम डेटा उपयोग करें। लेखांकन या कर प्रमाणन नहीं। केवल EUR में खरीद, क्रेडिट नोट नहीं। ALE प्रयोगात्मक और ऑफलाइन है। Docker और होस्टिंग के लिए स्वतंत्र स्वीकृति परीक्षण चाहिए।**

## 1. स्थापना

Python 3.13, परीक्षण के लिए Node.js, अंग्रेज़ी और स्पेनिश मॉडल वाला Tesseract, PDF के लिए Pango और Noto फ़ॉन्ट स्थापित करें। वर्चुअल वातावरण बनाकर निश्चित संस्करण निर्भरताएँ स्थापित करें। Windows पर PowerShell और `$env:` प्रयोग करें। निजी डेटा फ़ोल्डर रखें, पुराने `app.py` को सार्वजनिक न करें।

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
export BC_ROOT="$PWD/data" BC_TLS=0 BC_HOSTS=127.0.0.1 BC_ORIGIN=http://127.0.0.1:8765
python admin.py company Demo
# COMPANY_ID = returned identifier
python admin.py user COMPANY_ID demo-owner --role owner
python admin.py user COMPANY_ID demo-analyst --role analyst
python -m uvicorn secure_app:app --host 127.0.0.1 --port 8765
```
```powershell
.venv\Scripts\Activate.ps1
$env:BC_ROOT = "$PWD\data"
$env:BC_TLS = "0"
$env:BC_HOSTS = "127.0.0.1"
$env:BC_ORIGIN = "http://127.0.0.1:8765"
```

## 2. खाते और भूमिकाएँ

कंपनी और दो अलग स्वामी (या विश्लेषक और स्वतंत्र स्वामी) बनाएँ। CLI कम से कम 14 अक्षरों का पासवर्ड माँगता है; डिफ़ॉल्ट क्रेडेंशियल नहीं। लॉगिन करें और भाषा चुनें। पाठक केवल पढ़ता है, विश्लेषक प्रस्ताव देता है, स्वामी दूसरे उपयोगकर्ता के अनुरोध की समीक्षा करता है।

## 3. इनपुट प्रारूप

कृत्रिम डेमो से शुरू करें। नीचे मानक टेम्पलेट के ग्यारह फ़ील्ड हैं; ISO YYYY-MM-DD तारीख, kg, l, ud इकाइयाँ (g और ml मानकीकृत), VAT रहित EUR मूल्य। सकारात्मक मात्रा, कुल = शुद्ध + ढुलाई − छूट। UTF-8 CSV, एक शीट वाला XLSX बिना फ़ॉर्मूला/मैक्रो/बाहरी लिंक, या समर्थित संरचित PDF। प्रति फ़ाइल 2 MB, 10,000 पंक्तियाँ; बैच 2–20 फ़ाइलें, कुल 8 MB। हर प्रकार का इनवॉइस या कर फ़ॉर्म आयात नहीं होता।

```csv
supplier,invoice,line,date,product,unit,quantity,net_eur,shipping_eur,discount_eur,reported_total_eur
DEMO,INV-001,1,2026-01-01,ITEM,kg,10,100,0,0,100
```

## 4. ऑडिट और तुलना

ऑडिट चलाएँ। अंकगणितीय अंतर, संभावित डुप्लिकेट और कम से कम 10% मूल्य वृद्धि देखें। विरोधी ID और असंगत राशि तुलना से बाहर। समान उत्पाद व इकाई और 30 दिन के नवीनतम अवलोकन तुलना करें। संभावित बचत भुगतान या वास्तविक बचत नहीं। मासिक लागत केवल पात्र पंक्तियों की।

## 5. OCR समीक्षा

स्कैन PDF: अंग्रेज़ी/स्पेनिश OCR से पाँच पृष्ठ तक लिप्यंतरित करें; मूल से जाँचकर CSV सुधारें। मूल PDF, समीक्षित CSV और 10–1000 अक्षरों का औचित्य भेजें। बिना समीक्षा OCR गणना में शामिल नहीं; मूल का स्वतंत्र सत्यापन भी नहीं।

## 6. शासन

साक्ष्य और अलग आधार/खरीद संदर्भों के साथ समतुल्य कोड या घोषित बचत प्रस्तावित करें। दूसरा स्वामी स्वीकृत या अस्वीकृत करे; स्वयं की स्वीकृति निषिद्ध। सामान्य रिपोर्ट मसौदे हैं। वास्तविक (कृत्रिम नहीं) रिपोर्ट के लिए अंकगणितीय मिलान और स्वतंत्र समीक्षक के साथ जारी करने का अनुरोध करें। स्वीकृत रिलीज़ केवल JSON। स्थानीय शृंखला और साक्ष्य रखें।

## 7. दस्तावेज़ बुद्धिमत्ता

दस्तावेज़ बुद्धिमत्ता में समर्थित फ़ाइलें, वास्तविक/कृत्रिम वर्गीकरण, वैकल्पिक स्वीकृत टेम्पलेट ID और साक्ष्य भेजें। टेम्पलेट JSON में ग्यारह फ़ील्ड अलग मूल शीर्षकों से मैप हों, आपूर्तिकर्ता, विभाजक और संख्या प्रारूप का `spanish` बूलियन। दूसरा स्वामी मानकीकृत पंक्तियाँ जाँचे। समाप्त/निरस्त टेम्पलेट अमान्य। नीति परिवर्तन स्वतंत्र अनुमोदन से।

```json
{
  "mapping": {
    "supplier": "supplier",
    "invoice": "invoice",
    "line": "line",
    "date": "date",
    "product": "product",
    "unit": "unit",
    "quantity": "quantity",
    "net_eur": "net_eur",
    "shipping_eur": "shipping_eur",
    "discount_eur": "discount_eur",
    "reported_total_eur": "reported_total_eur"
  },
  "supplier": "DEMO",
  "delimiter": ",",
  "spanish": false
}
```
## 8. दस्तावेज़ ROI

दस्तावेज़ ROI हेतु दो स्वीकृत दस्तावेज़, 1 से पंक्ति संख्या, समान उत्पाद/इकाई और वर्गीकरण चुनें। खरीद आधार के बाद और नीति अवधि में (डिफ़ॉल्ट 180 दिन)। अतिरिक्त लागत दशमलव स्ट्रिंग। सकल कमी = (आधार इकाई मूल्य − वर्तमान) × वर्तमान मात्रा; शुद्ध = सकल − लागत; ROI % = शुद्ध/लागत ×100, शून्य लागत पर अपरिभाषित। भुगतान या कारण संबंध सिद्ध नहीं। निरस्तीकरण आश्रित ROI अमान्य करता है।

## 9. इतिहास और निर्यात

स्थानीय इतिहास खोलें, मसौदा PDF, JSON, alerts.csv या comparisons.csv डाउनलोड करें। भाषा केवल प्रस्तुति बदलती है, संग्रहीत राशि और साक्ष्य नहीं। PDF अधिकतम 20 चेतावनियाँ और तुलनाएँ; CSV/JSON में विवरण। मशीन फ़ील्ड और स्रोत पाठ मूल रहें; बिना अनुवाद निदान में स्पेनिश मूल शामिल है।

## 10. अनुकूली अधिगम

ALE अलग पर्यवेक्षित ऑफलाइन मॉड्यूल है। नीचे परीक्षण और कृत्रिम तनाव परीक्षण चलाएँ। SQLite में अवलोकन और उम्मीदवार रखता है, स्वतंत्र समीक्षा और कंपनी/वास्तविक-कृत्रिम अलगाव आवश्यक। उत्पादन इनवॉइस से अपने आप नहीं सीखता या वित्तीय नियम नहीं बदलता; स्वायत्त निर्णय हेतु उपयोग न करें।

```bash
python -m unittest adaptive_learning.test_learning
python -m adaptive_learning.stress --out /tmp/ledger64-ale --seed 20261126
```
## 11. परिनियोजन

स्थानीय HTTP डेमो केवल लूपबैक। उत्पादन में HTTPS, सही BC_ORIGIN और BC_HOSTS, सुरक्षित स्थायी वॉल्यूम, बैकअप/पुनर्स्थापन परीक्षण, कंटेनर स्वीकृति और भेद्यता स्कैन चाहिए। Compose, Caddy, Railway कॉन्फ़िगरेशन उपलब्ध; निजी डेटा प्रकाशित या सशुल्क सेवाएँ सक्रिय न करें। मार्केटिंग साइट अलग; सत्यापित HTTPS URL पर ही मेटाडेटा बनाएँ।

```bash
docker compose config
docker compose build
# Only after acceptance and with BC_DOMAIN configured:
docker compose up -d
```
## 12. गोपनीयता और बैकअप

MIT मूल कोड पर लागू, निर्भरताओं के अपने लाइसेंस। व्यक्तिगत पहचान, व्यावसायिक दस्तावेज़, क्रेडेंशियल, बैकअप, निजी मॉडल या लॉग कमिट न करें। प्रमाणीकरण और कंपनी डेटाबेस अलग बैकअप करें, नई कंपनी में पुनर्स्थापित करें, पहुँच सीमित रखें। स्थानीय शृंखला बाहरी एंकर नहीं। भेद्यता निजी तौर पर बताएँ।

```bash
python admin.py backup-auth /secure/auth-backup.sqlite3
python admin.py backup COMPANY_ID /secure/company-backup.sqlite3
python admin.py restore-new RECOVERY /secure/company-backup.sqlite3
```

