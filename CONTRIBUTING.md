# Contribuciones

Buscar incidencias y PR anteriores, reproducir el problema, crear una rama acotada, añadir una prueba de comportamiento, ejecutar `python scripts/check.py` y adjuntar evidencia. Utilizar commits convencionales (`fix:`, `docs:`, `test:`, `chore:`). Revisar cambios de Dockerfile, dependencias, autenticación y gobernanza. Comunicar vulnerabilidades por canal privado. No incluir credenciales, bases de datos ni documentos reales. No fusionar con regresiones ni declarar compatibilidad no ensayada.
